## [2.4.3] - 2026-06-05

### Добавлено
- **Выбор DFU-устройства.** Если в режиме DFU одновременно находятся несколько STM32, прошивальщик выводит список устройств (имя продукта, серийный номер, порт USB) и предлагает выбрать, какое прошивать; выбранное устройство передаётся в dfu-util через `-S <serial>`. Если устройство одно, оно просто показывается для подтверждения — выбирать не нужно. Идентификатор приёмника выводится в виде шаблона `XXXX-XXXX-XXXX-<group>-XXXX-XXXX`, чтобы 4-ю группу можно было сверить с тем, что показано на экране приёмника.
- **Понятное имя продукта** в списке выбора (например, `Malahit-Lite DFU`): на macOS через `system_profiler`, на Linux через sysfs, на Windows — по возможности через вызов PowerShell `Get-PnpDevice` (с откатом на `STM32 BOOTLOADER`).
- **Русский changelog** (`CHANGELOG_RU.md`) и прямая ссылка **Changelog** в шапке `README.md` и `README_RU.md`.

### Исправлено
- **Linux: серийный номер и имя читались как "UNKNOWN".** На некоторых конфигурациях (например, приёмник за USB-passthrough виртуальной машины) dfu-util не может прочитать строковые дескрипторы USB и сообщает `UNKNOWN`, хотя ядро закэшировало их при перечислении устройств. Теперь выбор устройства читает серийный номер и имя продукта из sysfs по пути USB, так что они остаются корректными (проверено в виртуалках с Arch и Ubuntu).
- **Вводящее в заблуждение сообщение о времени прошивки:** теперь говорит *"это занимает около 3 минут для 2 МБ"* вместо *"5-15 секунд"* в обоих скриптах.

### Изменено
- Более яркий (зелёный) баннер в `flash_MLite880.sh`.
- Версия скрипта поднята до **2.4.3** в `flash_MLite880.sh`, `flash_MLite880.bat`, `README.md` и `README_RU.md`.

## [2.4.2] - 2026-06-05

### Исправлено
- **Несколько DFU-устройств больше не блокируют прошивку** (issue #1) — теперь прошивальщик явно указывает STM32 через `dfu-util -d 0483:df11,0483:df11`, поэтому второе DFU-совместимое устройство на шине USB (например, веб-камера ноутбука в run-time-режиме DFU) больше не заставляет dfu-util прерваться с ошибкой *"More than one DFU capable device found"*. Обе пары VID:PID обязательны, потому что одна пара фильтрует только run-time-устройства, но не те, что уже находятся в режиме DFU (проверено на реальном железе с dfu-util 0.11). На Windows значение берётся в кавычки, чтобы `cmd.exe` сохранил запятую.
- **Windows: ложное сообщение "Flashing failed"** — `flash_MLite880.bat` определял успех опросом шины USB после прошивки, а это подвержено состоянию гонки (в виртуалке устройство может ещё на мгновение появляться сразу после `:leave`). Теперь успехом считается код выхода dfu-util 74 (ожидаемая ошибка `get_status` после `:leave`) или 0, что соответствует реально записанной прошивке. Индикатор прогресса в реальном времени сохранён.

### Изменено
- **Меню прошивок теперь показывает самую новую версию первой и выбирает её по умолчанию** — нажатие Enter прошивает последнюю версию. Сортировка идёт по дате `YYYYMMDD` в имени файла, поэтому остаётся корректной даже по мере роста нумерации версий (например, v1.100 или v10.x).
- Версия скрипта поднята до **2.4.2** в `flash_MLite880.sh`, `flash_MLite880.bat`, `README.md` и `README_RU.md`.

## [2.3.0] - 2026-05-29

### Добавлено
- **Arch Linux: интерактивная автоустановка** — если `dfu-util` отсутствует, скрипт теперь автоматически предлагает установить его через `pacman` (`sudo pacman -Sy --noconfirm dfu-util`). Тот же интерфейс в один клик, что и для Debian/Ubuntu. Проверено на live-ISO Arch Linux.
- **Fedora / RHEL: интерактивная автоустановка** — тот же процесс автоустановки через `dnf install -y dfu-util`.
- **openSUSE: интерактивная автоустановка** — тот же процесс автоустановки через `zypper install -y dfu-util`.

### Изменено
- Переработан путь установки под Linux в `flash_MLite880.sh`: общая логика вынесена во вспомогательную функцию `_install_dfu_util_pkg`, чтобы избежать дублирования между четырьмя менеджерами пакетов. Существующая ветка `apt` ведёт себя так же, как в v2.2.0.
- Версия скрипта поднята до **2.3.0** в `flash_MLite880.sh`, `flash_MLite880.bat` и `README.md`.

## [2.0.0] - 2026-05-24

### Добавлено
- **macOS: интерактивная автоустановка** — если Homebrew и/или `dfu-util` отсутствуют, скрипт автоматически предложит их установить.
- **Debian/Ubuntu: интерактивная автоустановка** — если `dfu-util` отсутствует, скрипт автоматически предложит установить его через `apt`.
- **Автоматическое повышение прав до `sudo` на Linux/macOS**, когда отказано в прямом доступе к USB DFU — больше не нужно вручную добавлять `sudo` в начале.
- **Предварительное обнаружение USB-устройства** на всех платформах до выбора прошивки: `lsusb` на Linux, `system_profiler` на macOS, `pnputil` на Windows. Пользователь получает понятное сообщение ("устройство не в режиме DFU" или "отсутствует драйвер") вместо невнятных ошибок dfu-util.
- **Windows: тихая установка драйвера WinUSB** — если устройство STM32 BOOTLOADER присутствует на шине USB, но драйвер WinUSB отсутствует, `.bat` сам повышает права до администратора и запускает входящий в комплект `qmk_driver_installer.exe`. Клики не нужны. Затем он программно перезапускает порт USB (`pnputil /restart-device`), чтобы привязать драйвер без физического переподключения.
- Добавлен `qmk_driver_installer.exe` (6.19 МБ, SHA256 в сопроводительном файле `qmk_driver_installer.exe.sha256`) для тихой установки WinUSB.
- Добавлена папка `tools/` со скриптами очистки для тестирования и сброса окружения: `cleanup_drivers.bat` (Windows, обрабатывает INF-файлы в UTF-16) и `cleanup_mac.sh` (macOS).

### Исправлено
- **Ложноположительный сбой при успешной прошивке (Exit Code 74)**: оба скрипта, `.sh` и `.bat`, теперь корректно трактуют Exit Code 74 в сочетании с отключением устройства (или проверкой по логу) как успешную прошивку.
- **Windows: ложноположительный успех при сбое драйвера**: исправлена ошибка, при которой сбой `LIBUSB_ERROR_NOT_SUPPORTED` на Windows ошибочно сообщался как успех. Скрипт `.bat` теперь строго проверяет, что код выхода равен 74 *и* устройства больше нет на шине, сохраняя при этом нативный индикатор прогресса `dfu-util` в реальном времени (избегая проблем с отрисовкой возврата каретки из-за каналов PowerShell).
- Подсказка про `udev` после сбоя прошивки теперь срабатывает на всех дистрибутивах Linux (`linux*` в `$OSTYPE`).

### Изменено
- Версия скрипта поднята до **2.0.0** в `flash_MLite880.sh` и `flash_MLite880.bat`.

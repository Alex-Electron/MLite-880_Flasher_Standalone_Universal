Troubleshooting tips

After the write

  1. The flasher takes the receiver out of DFU itself: it sends the leave request and resets USB — the same finish as dfu-util with “:leave”.
  2. If the screen stays dark, press button “1” or switch the receiver off and on again (as the MLite-880 manual says). The firmware is already written.
  3. If it still will not start, put the receiver into DFU again and repeat the write.

A dark screen right after the write is not a brick: the STM32 system bootloader stays available, so the receiver can always be put back into DFU and flashed again.

Receiver not found

Check DFU mode (hold “1”, power on, wait 3 s, release “1”), the power supply and the USB cable: it must carry data, not only charge. Connect directly, without a hub, and disconnect other STM32 devices in DFU mode.

Device busy / cannot be opened

Only one program can use the DFU interface at a time. Close dfu-util, STM32CubeProgrammer, other flashers and other tabs with this page, then connect again.

Windows · WinUSB

If the receiver is missing from the browser list or the browser cannot open it, assign the built-in WinUSB driver to it once:

  1. Download Zadig from its official website and run it as administrator: zadig.akeo.ie ↗
  2. Enable List All Devices in the Options menu.
  3. Select only STM32 BOOTLOADER (or Malahit-Lite DFU) with USB ID 0483 DF11.
  4. Select WinUSB and click Replace Driver (or Install Driver).
  5. Reconnect USB and click the connect button again.

Do not replace the driver of any other USB device.

Alternative: the flash_MLite880.bat script from this repository installs WinUSB automatically on its first run.

macOS · USB access

macOS does not need a separate DFU driver.

  1. On a Mac with Apple silicon, unlock the computer, connect the receiver and click “Allow” in the USB accessory prompt.
  2. If the prompt was denied, open System Settings → Privacy & Security → Allow accessories to connect and choose Ask for New Accessories or Automatically When Unlocked.
  3. If the receiver is missing from the browser list, open System Information → USB. If 0483:DF11 is listed, check the browser or access settings; if not, check the cable, power and DFU mode.

Linux · udev

If the browser reports an access error (Permission denied), create a udev rule for the receiver. The command works on current Debian/Ubuntu/Mint, Fedora/RHEL, Arch/Manjaro and openSUSE:

1. Create the rule and reload settings

printf '%s\n' 'SUBSYSTEM=="usb", ATTR{idVendor}=="0483", ATTR{idProduct}=="df11", MODE="0660", TAG+="uaccess"' | sudo tee /etc/udev/rules.d/70-mlite-dfu.rules >/dev/null && sudo udevadm control --reload-rules && sudo udevadm trigger --subsystem-match=usb

2. Fully unplug the receiver, reconnect it in DFU mode and connect again in the browser.

If the terminal says udevadm was not found, first install the system package for your distribution:

Debian / Ubuntu / Mint
sudo apt update && sudo apt install -y udev
Fedora / RHEL / Rocky / Alma
sudo dnf install -y systemd-udev
Arch / Manjaro
sudo pacman -S --needed systemd

If access is still denied, sign out of your Linux account, sign in again and reconnect USB.

Do not refresh while flashing

While the write is running, the browser warns you if the page is refreshed or closed. If you confirm leaving, the USB transfer stops and the firmware remains incomplete.

After an interruption, put the receiver into DFU again and flash from the beginning. Do not disconnect power or USB until the success message appears.

Switching to another tab or minimizing the window during the write is fine: flashing continues at full speed.

## 📥 Впервые на GitHub? Сначала скачайте набор

Аккаунт на GitHub и знание Git не нужны. Весь набор — это одна папка с файлами, и скачивается она единым ZIP-архивом.

1. Откройте страницу проекта: **https://github.com/Alex-Electron/MLite-880_Flasher_Standalone_Universal**
2. Нажмите зелёную кнопку **`< > Code`** над списком файлов.
3. В выпавшем меню выберите **Download ZIP**.
4. Найдите только что скачанный файл `...-main.zip` и распакуйте его:
   - **Windows** — щёлкните по ZIP правой кнопкой и выберите *Extract All*.
   - **macOS** — дважды щёлкните по ZIP.
   - **Linux** — щёлкните правой кнопкой и выберите *Extract Here* либо выполните в терминале `unzip <file>.zip`.
5. Откройте распакованную папку. Файлы прошивок `.bin`, скрипты прошивальщика и драйверы для Windows лежат прямо внутри.

Нужна старая или конкретная версия? Откройте страницу [Releases](https://github.com/Alex-Electron/MLite-880_Flasher_Standalone_Universal/releases), выберите релиз и скачайте **Source code (zip)** в разделе *Assets*.

Когда папка окажется на компьютере, переходите к шагам прошивки ниже.

## 🚀 Как прошить прошивку

1. Все актуальные файлы прошивок `.bin` (на 11 июня 2026 года) уже лежат в этой папке. Если в будущем выйдут новые версии, просто скиньте новые `.bin` сюда же — прошивальщик подхватит их автоматически.
2. Подключите приёмник к компьютеру по USB.
3. Переведите приёмник в **режим DFU**: зажмите кнопку **1**, включите приёмник, подождите 3 секунды и отпустите кнопку **1**. Приёмник перейдёт в режим DFU.
4. Запустите прошивальщик:
   - **Windows:** дважды щёлкните по `flash_MLite880.bat`.
   - **macOS / Linux:** откройте терминал и выполните `./flash_MLite880.sh`.
5. Выберите версию прошивки в меню на экране.

Вот и всё. Начиная с v2.0.0 скрипт автоматически:
- определяет, находится ли приёмник в режиме DFU и виден ли на шине USB;
- на macOS — предлагает автоматически установить Homebrew и `dfu-util`, если их нет;
- на Debian/Ubuntu — предлагает автоматически установить `dfu-util` через `apt`;
- на Linux/macOS — перезапускает себя с `sudo`, если нет прямого доступа к USB;
- на Windows — обнаруживает отсутствие драйвера WinUSB и ставит его автоматически (повышение прав администратора берёт на себя).

## 🛠️ Настройка и решение проблем

### 🪟 Windows: USB-драйвер
С версии v2.0.0 файл `.bat` ставит драйвер WinUSB **автоматически**, когда это нужно. Если устройство STM32 BOOTLOADER есть на шине USB, но драйвер WinUSB отсутствует, скрипт:

1. Запрашивает права администратора (одно окно UAC).
2. Запускает встроенный `qmk_driver_installer.exe` с ключами `--vid 0x0483 --pid 0xdf11 --type 0` — WinUSB ставится без лишних действий, нажимать ничего не надо.
3. Сам переходит к выбору прошивки.

**На заметку при первом запуске:** так как установщик — это неподписанный бинарник из релиза на GitHub, при самом первом запуске Windows SmartScreen может показать предупреждение. Нажмите один раз **More info → Run anyway**, и Windows запомнит файл по хешу.

Если с автоматической установкой что-то пойдёт не так, скрипт откатится к интерактивной утилите Zadig. Драйвер можно поставить и вручную:
1. Запустите `tools/zadig-2.9.exe`.
2. Нажмите `Options` -> `List All Devices`.
3. Выберите `STM32 BOOTLOADER` из списка.
4. Убедитесь, что целевой драйвер — `WinUSB`.
5. Нажмите `Install Driver` и дождитесь завершения.

### 🍎 macOS
1. Скрипт **сам предложит установить** `Homebrew` и `dfu-util`, если их нет.
2. Права root (sudo), как правило, **не нужны**.
3. Если устройство не находится, проверьте в **System Settings > Privacy & Security**, что USB-устройства разрешены.

### 🐧 Linux (Ubuntu, Debian, Fedora, RHEL, Arch, openSUSE и т. д.)

**Debian / Ubuntu:**
Скрипт **сам предложит установить** `dfu-util` через `apt`, если его нет.

**Другие дистрибутивы:**
Установите `dfu-util` вручную под свой дистрибутив:
```bash
# Fedora / RHEL
sudo dnf install dfu-util
# Arch
sudo pacman -S dfu-util
# openSUSE
sudo zypper install dfu-util
```

По умолчанию прямой доступ к USB в Linux требует прав root. Скрипт решает это сам — если ловит ошибку доступа, перезапускается с `sudo` (пароль спросят один раз).

Если хотите вообще обойтись без `sudo`, один раз поставьте правило udev:
```bash
echo 'SUBSYSTEM=="usb", ATTR{idVendor}=="0483", ATTR{idProduct}=="df11", MODE="0666"' | sudo tee /etc/udev/rules.d/50-dfu-malachite.rules
sudo udevadm control --reload-rules
```
После этого отключите и снова подключите приёмник. Дальше скрипт будет работать без повышения прав.

## 🧰 Дополнительные утилиты в комплекте

В папке `tools/` лежат вспомогательные скрипты, которые приводят систему в порядок после прошивки или тестов:

- **`tools/cleanup_drivers.bat` (Windows):** удаляет установленные драйверы STM32 WinUSB из системы. Пригодится при конфликтах драйверов или когда нужно начать с чистого листа.
- **`tools/cleanup_mac.sh` (macOS):** удаляет `dfu-util` и предлагает полностью снести Homebrew с Mac. Удобно, чтобы вернуть тестовую систему в исходное состояние.

## 🔍 Технические нюансы и поведение ОС

Прошивальщик использует несколько технических приёмов, чтобы всё работало одинаково гладко на разных платформах:

- **Код выхода 74 (на всех системах):** после удачной прошивки `dfu-util` отправляет микроконтроллеру команду `:leave`. Устройство тут же перезагружается и отваливается от шины USB. Из-за этого `dfu-util` не может корректно закрыть соединение и возвращает `Exit Code 74 (Error during download get_status)`. Скрипты ловят это:
  - Скрипт **Windows (`.bat`)** после прошивки опрашивает шину USB. Если DFU-устройство исчезло — значит всё прошло как надо, и это засчитывается как "Success".
  - Скрипт **macOS/Linux (`.sh`)** читает `stdout` в реальном времени. Если он видит фразу *"File downloaded successfully"*, то подменяет код выхода и засчитывает "Success".
- **Перезапуск PnP (Windows):** когда драйвер WinUSB ставится автоматически в первый раз, Windows нужно "привязать" его к уже подключённому устройству. Чтобы не заставлять вас физически вытаскивать и вставлять приёмник, скрипт `.bat` программно перезагружает USB-порт через `pnputil /restart-device`.
